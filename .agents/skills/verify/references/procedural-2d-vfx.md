# 原创 JavaScript 2D 技能动画：制作与验证

适用范围：仓库根目录，`public/jianghu-sixteen/crane.js` 与 `animation.html`。已完成的原型依据为提交 `41a800d5c335d94e5cd7bc80ae4c7a3c070e5a90`；历史检查见 `docs/jianghu-sixteen/VERIFY.md`。这里记录可复用方法，不把历史结果当作未来版本的通过证据。

## 1. 从意图拆到动作

先写出物件、变化、空间范围、起止状态，再编码。纸鹤实例：纸张 → 鹤形 → 三路曲线飞行 → 展开为符 → 朱砂围合 → 纸角消散。最新用户要求是无山水大景、俯视、单个技能范围。任何招式都应有可辨认的动作变化，不依赖换颜色区分。

静态概念图由 image_gen 分别生成，保留原始PNG、提示词、版本和哈希。它只探索外形与色彩，不能证明动作成立。当前动画没有读取生成PNG；它由Canvas绘制原创几何形状，不是图片平移缩放、视频模型输出或第三方GIF改制。三个一念逍遥参考链接及观察边界见 `docs/jianghu-sixteen/REFERENCES.md`。

## 2. 实际 .js 结构

`crane.js` 暴露 `duration = 4.8`、`phase(t)`、`drawCrane(context, t)`。绘制函数根据给定时间重建整帧；播放状态和UI放在 `animation.html`。调用绘制函数只用于开发，最终验收仍需真实浏览器。

- 画布逻辑尺寸960×640；每帧清空，再画深青背景和低对比地面标记。地面标记属于背景，可以保留。
- `sat`限制进度到0–1；`smooth`采用 `x*x*(3-2*x)` 缓动；`mix`在两个值之间插值。
- 纸鹤外轮廓与矩形纸张使用同样数量的顶点；逐点插值实现折叠/展符。附加多边形画头颈与明暗面，正弦位移画拍翼。这是二维形状变换，不是真实纸张物理或三维折纸。
- 每只鹤的位置由起点到终点的插值加正弦偏移构成曲线；三个索引有不同横向偏移和轻微出发延迟。沿路径较早的位置画细小淡点作为尾迹。
- 鹤到达后展开成矩形；通过裁切区域逐步露出朱砂笔画，三边线分段生长。约3.12秒使用短促的径向渐变脉冲强调生效。
- 消散阶段用确定性的索引角度生成27个纸角碎片，再降低透明度。不要每帧使用未固定的随机数，否则回看同一时间不能复现。
- 局部变换/透明度用 `save()` / `restore()` 包住，避免影响下一层。`t <= 0` 或 `t >= 4.5` 只保留背景。

时序：0–0.7折纸，0.7–2飞行，2–2.7展符，2.7–3.5围合，3.5–4.5消散，4.5–4.8归静。这是项目设计值，非参考GIF实测值。

## 3. 播放器职责

用 `requestAnimationFrame` 获取时间差，乘速度推进时间，再调用绘制；不要按帧数推进，否则刷新率改变会影响时长。播放器负责暂停、重播、循环取余、非循环末帧停止、时间滑块和精确时间输入。跳转先暂停并限制到0–4.8秒；隐藏页面时暂停，避免回来后时间突然大幅跳跃。

新技能可以沿用“纯时间绘制函数 + 独立播放器”的分工，但应根据自己的动作重新设计轮廓、路径与时序，不直接复制纸鹤参数。

## 4. 启动与真实操作路径

前提：Node/npm与依赖安装；新检出先 `npm ci`。根目录运行：

```sh
npm run verify
npm run preview -- --port 4193 --strictPort
```

确认Vite报告本地地址，真实浏览器打开 `http://127.0.0.1:4193/jianghu-sixteen/animation.html`，看到标题“纸鹤衔令 · 俯视技能动画”、Canvas与播放按钮才算到达用户表面。4193若已占用，先识别现有服务或选择其他空闲端口，记录真实URL；不要终止未知进程。使用当前支持的浏览器工具，遵循其文档。此前成功工具是Codex in-app browser / cua_repl。

最小验收路径：

1. 点击播放，观察时间与画面同时推进；暂停后确认停住。实际观察一整轮折鹤、飞行、展符和退场，静态截图不能替代连续播放。
2. 精确时间输入1.40并点击“查看此帧”：应看到三只鹤；2.90：应看到三张符与围合线；4.80：应只剩背景。
3. 相邻探针：从4.80倒退到1.40，确认鹤重新出现，没有上一次残影。反复重播，不增加纸鹤或符纸数量。
4. 关闭循环，从头播放，应在4.80停止；开启循环，实际观察跨越末帧后继续。选择0.25倍速并观察；只看到选项被选中不能声称已测量速度正确。
5. 390×844窄屏检查画布、控件与横向溢出；查看控制台；恢复原尺寸。
6. 如果修改评审页，逐张切换17项并等待当前图片解码完成，再记录 `complete` 与 `naturalWidth`。快速切换后立刻读到0不等于图片损坏，也不能提前报加载PASS。

记录候选SHA、工作树是否有改动、精确URL、每步观察和截图。写入 `docs/verification/<date>-<scope>.md`；原始证据使用项目忽略的输出目录并在报告中注明保留位置，用户要求交付的GIF才放入public版本目录。不得把个人绝对路径、凭据或会话资料提交到公共仓库。

## 5. 从真实画面导出 GIF

已成功路线：用可见“精确时间”输入和“查看此帧”按钮，0到4.8秒按0.08秒采样，共61次；每次保存浏览器全页截图。逐帧裁出同一个画布区域，用Python Pillow编码，`duration=80`、`loop=0`、`disposal=2`。Pillow仅用于截图裁切和动画编码，不修改原始AI概念图。

关键经验：浏览器截图clip坐标与滚动后的 `getBoundingClientRect()` 曾发生偏移。最终采用全页截图，再用已核实的文档坐标裁切。旧导出区域是 `(135,161,895,668)`，得到760×507画布；这些坐标只适用于当时布局，不能硬编码到新视口。重新测量并检查首帧、中间帧和末帧，确保没有标题、按钮或裁掉的技能。

比较原始RGB首尾帧像素，确认清空一致；检查中间帧确实不同。GIF编码器可能合并相邻相同帧，因此区分“61次采样”与“编码后帧数”。含末帧停留后总时长约4.88秒，低于浏览器实时渲染的流畅度。GIF是动作评审媒介，不是透明引擎贴图、精确性能测量或视频模型结果。

## 6. 边界、发布和清理

当前简化：三张纸分别折成鹤，尚未实现一纸分三鹤；没有角色、伤害、声音、Godot或设备性能验收。参考GIF仅有限观察，逐帧parity未完成；用户的题材偏好不等于生成图/动画批准。将待完成事项写入报告，不能被机器检查PASS覆盖。

本地页面的临时选择仅存localStorage；Airtable正式选择必须由用户明确选择后写入并回读。原图不可覆盖，修订增加版本。

合并main会触发Pages工作流。部署成功只说明发布流程通过；要声明公共页面验收，必须在实际Pages动画URL操作并核对 `build-info.json` 的SHA。docs-only补充的runtime verdict为SKIP，不重用旧截图给新版本背书。
