# 青岚剑阵动态特效验证协议

本协议定义如何验证，不代表以下检查已经执行。沿用SKILL.md的机器、浏览器、发布检查。

## 固定测试条件

记录日期、源码SHA、精确URL、build-info、浏览器/系统、视口、DPR、质量档、相机、播放速度、循环和各层开关。先用生产构建，发布时再查实际Pages。相机固定为reset状态；高画质/全部层/1×作为主样本。不要跨相机或不同背景直接比较面积/亮度。

## 动态检查矩阵

| ID | 操作与证据 | 通过标准 |
|---|---|---|
| VFX-01 | 连续播放完整3.2s至少两轮；保留可定位URL/SHA的录像或带时间的连续观察 | 蓄势→斩击→消散顺序清楚，轮次之间没有残留或突跳；单张截图不算动态验证 |
| VFX-02 | 暂停采样0、0.80、1.09/1.10/1.11、1.19/1.20/1.21、1.48、1.79/1.80/1.81、2.50、3.20；记录显示的实际时间 | 关键阶段和边界可重现；没有非设计性整层闪断。1.20为视觉cue；不得由模拟血量证明碰撞发生 |
| VFX-03 | 看一主剑六飞剑在展开/聚集/斩击中的连续轨迹；必要时关闭其他层观察剑体 | 能读出主次、攻击方向及阵列组织；无明显穿帮/无意瞬移；遮挡时不靠一张截图断言数量错误 |
| VFX-04 | 分别关闭/恢复swords、sigil、ribbons、particles、bloom；每层在其活跃阶段观察动态图 | 对应层真实消失/恢复；拖尾与剑体方向一致，法阵不抢主斩击，粒子不盖住轮廓；非活跃阶段开关无变化不能算通过 |
| VFX-05 | 正常速度看峰值，0.25×辅助看拖尾/边缘/噪声消散；保存峰值与余韵观察 | 蓄势与爆发有强弱差；消散有可读的退场过程；无非预期白屏/方形贴片/硬切。美术判断给出理由，不仅填PASS |
| VFX-06 | 在3.20观察清空；回退0.80，再来回seek并恢复播放 | 特效在末帧清空（背景/地台可在），回退重现；不积累鬼影或重复事件 |
| VFX-07 | 1×与0.25×使用相同起止段读取媒体/单调时钟时差与效果时间差 | 只选中0.25×只能证明控件生效；若宣称倍率准确，应预设误差容限并记录测量值，不能用工具调用间隔精确计时 |
| VFX-08 | desktop与390×844；high/low对照同阶段，bloom关闭再恢复 | 核心剑阵及三阶段仍可读，无裁切遮挡；low减少粒子可以接受。桌面窄视口不等于真机性能 |
| VFX-09 | 查看控制台；相机orbit/reset、标签页隐藏/恢复、模式切换、可支持时注入WebGL context loss | 无应用错误；中断恢复符合当前实现，不能卡在旧特效。未实际操作的路径写NOT_RUN |

如工具不能精确seek，记录实际采样时间与误差，未覆盖的边界保留NOT_RUN；不能根据源码或滑块HTML初始value宣称已观察该帧。

## 一念逍遥动态对照

先完成来源文档的候选验证。并排比较同类型动作：聚势/飞剑组织、加速/指向性、峰值/命中cue、尾迹/墨化四项。分别写“原片实际观察”“青岚实际观察”“差距/建议”，附两边时间位置。只做结构/风格对照时无需相同时长；要做逐帧定量比较，必须先确认来源帧率、播放/游戏速度及剪辑情况。没有证据，不标相似度百分比，不宣称复刻。

新发现的美术问题不能被构建PASS覆盖。技术错误FAIL阻断技术发布；参考未观看保持NOT_RUN，不阻断仅更新验证文档的合并。此次仅修改协议时，复查链接/结构、运行仓库必要检查并报告文档范围，不能把过去的浏览器PASS记成本轮新验收。真机性能须另记设备、并发量、分辨率、测量方法和预先约定预算。
