## Components and state
List components, observed states and untested states separately. Include empty/loading/error states only where meaningful.

## Interaction
For each control record intent, trigger, state change, feedback and keyboard/touch behavior. A static reference does not prove behavior.

## Layout and accessibility
Record hierarchy, text growth, contrast checks, focus order, overflow, safe areas and reduced-motion behavior.

## Acceptance
Link declared checks and actual evidence; keep unfinished requirements open.
